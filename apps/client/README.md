# @gymix/client

Клиент Gymix на React + Vite. Использует локальную PGlite (PostgreSQL в WASM) и двустороннюю синхронизацию с API. После первого входа и загрузки production-кэша основные функции доступны без сети.
Домен (`@gymix/structures`, `@gymix/catalog`, `@gymix/generator`, `@gymix/db`)
переиспользуется тот же, что и на сервере.

## Структура

| Папка | Что там |
|---|---|
| `src/screens/` | Экраны приложения (тип, объём, структура, предпросмотр, выполнение, история, прогресс, настройки и т.д.) |
| `src/components/` | Переиспользуемые компоненты (кнопки, табы, сегменты, график) |
| `src/lib/` | Домен клиента: репозитории поверх PGlite, черновики, таймеры, форматирование |
| `src/hooks/` | React-хуки (`useDb`, `useAuth`) |
| `src/data/auth/` | Сессия аккаунта, запросы API, обновление токенов |
| `src/data/sync/` | Транзакционная очередь, загрузка снимков, конфликты, резервная выгрузка |
| `src/data/local/` | Worker PGlite, миграции и начальное заполнение |
| `src/styles/` | CSS по слоям: токены, глобальные стили, стили экранов и компонентов |

## Команды

```bash
pnpm --filter @gymix/client dev        # vite dev server, http://localhost:5173
pnpm --filter @gymix/client build      # tsc -b && vite build → dist/
pnpm --filter @gymix/client preview
pnpm --filter @gymix/client typecheck
```

В бандл попадает WASM-движок PGlite и данные каталога — сборка крупная
(десятки МБ в `dist/assets`), это ожидаемо для локальной БД в браузере.

Локальная БД работает в общем для вкладок worker. Миграции версионируются и применяются к существующим данным. Production-сборка кэширует интерфейс, каталог и WASM через Service Worker для повторного открытия без сети. Каждый аккаунт использует отдельную локальную базу. Изменения и очередь отправки сохраняются атомарно. Подробности протокола и ограничения описаны в `docs/backend.md`.

`pnpm --filter @gymix/client test` проверяет авторизацию и синхронизацию с реальным Hono-приложением и изолированными PGlite-базами.
